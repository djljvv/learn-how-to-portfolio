Read a tag from left to right

<a class="card-link" href="#about">About</a>
  1. < and > mark tag boundaries. a is the element name. class and href are attributes; = connects each attribute name to a quoted value.
  2. About is the visible text between the tags. </a> closes the element; the slash means “end this element.” Together, the tags and their contents form an element.
  3. An element inside another is a child of that parent. Most elements have closing tags; void elements such as meta, link, and br do not. The <> symbols do not appear on the rendered page.
  4. Examples below display HTML as text. The browser needs escaped characters in the tutorial source to show it that way; the displayed code is what you copy into an HTML file.

ARIA: names, state, and announcements

aria-label supplies an accessible name; aria-labelledby points to the id of visible naming text. aria-hidden="true" excludes decoration. aria-pressed describes toggle state. aria-live="polite" announces updates when convenient; aria-atomic="true" requests the whole updated message. These attributes describe behavior; JavaScript still performs the update.

<p class="filter-status" aria-live="polite" aria-atomic="true">Showing all 3 examples.</p>

Read the parts:

  • aria-label / aria-labelledby — The first contains the name itself; the second contains the id of an element whose text supplies the name. Do not put # before that id.
  • aria-live="polite" — The paragraph becomes a live region. Later text changes can be announced without interrupting the reader immediately.
  • aria-atomic="true" — When that region changes, announce the complete status phrase, so a lone updated number is not confusing.
  • aria-pressed / aria-hidden — Pressed describes a toggle’s state; hidden excludes decoration from assistive technology. aria-hidden does not visually hide content; the HTML hidden attribute does.

Used here: Navigation, section headings, learning-notes switch, filters, and counter.

Attributes: class, id, and data-*

Attributes configure an opening tag. class is a reusable styling hook; id must be unique within a page and can be a link destination. data-category and data-filter hold strings read by JavaScript through dataset.

<article class="project-card" data-category="css">…</article>

Read the parts:

  • class="project-card" — class is the attribute name; the quoted text is its value. The CSS selector .project-card and the JavaScript query use that same class name.
  • id="projects" — An id identifies one destination. Write it without # in HTML; add # when referring to it in a link or selector.
  • data-category="css" — The category is custom data, not a built-in visual style. The word css is compared with a filter’s data-filter value; it does not load a CSS file.

Used here: Project cards and filter buttons in index.html.

button and type

A button performs an action. type="button" avoids submitting a form. JavaScript listens for click, which also supports keyboard activation of a native button. Use an anchor for page navigation instead.

<button type="button" data-filter="css" aria-pressed="false">CSS</button>

Read the parts:

  • <button>CSS</button> — The text between the tags is the visible label. Both tags belong to one button element.
  • type="button" — This button performs an action without submitting a form. This attribute alone does not implement the filter.
  • data-filter / aria-pressed — The custom filter value tells JavaScript what to select. aria-pressed tells readers which filter is active and lets CSS style that state.

Used here: Filters, counter, and notes switch.

Comments: <!-- … -->

An HTML comment explains nearby markup for people reading the source. It is not visible page content, but anyone viewing source can read it.

<!-- This link opens a sibling document. -->

Read the parts:

  • <!-- and --> — These delimit the beginning and end of a comment. Everything between them is explanatory source text.
  • A sibling document — This means another file in the same folder. The comment describes the next link; it does not create that link.

Used here: All HTML files.

details, summary, and open

details creates a disclosure widget; its first summary names the clickable heading. The boolean open attribute starts it expanded. Omitting open starts it collapsed; open="false" would still count as present and therefore open.

<details open><summary>Meet HTML</summary><p>The lesson goes here.</p></details>

Read the parts:

  • <details open> — This starts the disclosure and sets its initial state. open has no value here because it is a boolean attribute.
  • <summary>Meet HTML</summary> — The summary is the built-in activation target. Place it first inside details.
  • <p>…</p> followed by </details> — The paragraph is the collapsible content. The final closing tag ends the whole widget, after all its content.

Used here: The three code lessons on the homepage.

dl, dt, and dd

dl groups terms and descriptions, dt names a term, and dd explains it. Each glossary wraps a term-description pair in a div with an id so the index can link directly to it.

<dl><div id="term"><dt>HTML</dt><dd>The structure of a page.</dd></div></dl>

Read the parts:

  • <dl> — Begins the description list. It is not a numbered list, so the browser does not add step numbers.
  • <dt>HTML</dt> — Names the term being defined. The stylesheet makes this term visually prominent.
  • <dd>The structure of a page.</dd> — Contains the definition. The surrounding div groups this term and description and gives the pair a linkable id.

Used here: These three dictionaries.

DOCTYPE, html, head, and body

DOCTYPE opts into standards mode. html is the root element and lang="en" declares the content language. head contains metadata and resource links; body contains the visible document. Most elements need a closing tag; meta and link are void elements and do not.

<!DOCTYPE html>
<html lang="en">
  <head><title>A lesson</title></head>
  <body>Content</body>
</html>

Read the parts:

  • <!DOCTYPE html> — This is a declaration, not a visible element or a tag that needs a closing partner.
  • <html lang="en"> — html contains the document. lang is an attribute; en is the language code for English.
  • <head> versus <header> — head holds page metadata and resource links. header is a visible introductory region inside body; the two names are not interchangeable.
  • Nesting — Close an inner element before closing its parent: title closes before head, and body closes before html. Indentation helps you see those relationships.

Used here: The frame of every page.

Entities: &lt;, &gt;, &amp;, and &quot;

Character references display reserved characters: &lt; is <, &gt; is >, &amp; is &, and &quot; is a double quote. Escaping angle brackets makes sample markup visible instead of creating elements. To display the literal text &lt;, source uses &amp;lt;.

<code>&lt;a href=&quot;#about&quot;&gt;About&lt;/a&gt;</code>

Read the parts:

  • &lt; and &gt; — Each reference begins with & and ends with ;. The browser displays < and > instead of treating them as markup delimiters.
  • &quot; — Displays a double quote. In this example it is part of the displayed sample attribute, not an attribute on the surrounding code element.
  • The rendered result — The example displays the literal text <a href="#about">About</a>. It does not create a clickable About link.

Used here: All visible HTML code examples.

Headings and text: h1–h3, p, br

h1 names the page, h2 names a major section, and h3 names a card or subtopic. p creates a paragraph; br inserts an intentional line break without starting a new paragraph. Heading levels express hierarchy, not font size.

<h2>Every good portfolio<br>opens a door.</h2>

Read the parts:

  • h1, h2, h3 — The number indicates heading level. This site uses one page title, section headings beneath it, then card or lesson headings.
  • <br> — Inserts a line break inside the h2. It has no closing tag and is not a replacement for a new paragraph.
  • <p> — Creates a paragraph of prose. Use CSS margin and line-height to control spacing rather than adding repeated br elements.

Used here: The hero, section introductions, and card titles.

hidden

This boolean attribute removes content from display and the accessibility tree. JavaScript removes its effect with element.hidden = false. Presence is what matters: hidden="false" still hides. The stylesheet explicitly preserves hidden against grid and flex display rules.

<button type="button" id="counter-button" hidden>Try a click</button>

Read the parts:

  • hidden in the opening tag — Hides the button initially, even though its text still exists in source. It is deliberately written without ="true".
  • button.hidden = false — This is JavaScript, not an HTML attribute. It reveals the already-existing button once the behavior can run.

Used here: Controls that only become available once JavaScript initializes.

Inline text: span, em, strong, small, b, i

span is a neutral inline wrapper. em marks stress emphasis and strong marks importance. small represents side text. b draws attention without extra importance; i represents alternate voice. Here empty i elements and a b arrow are purely decorative inside aria-hidden artwork. Classes provide their visual styling.

<p>My wardrobe is <span class="highlight-css">CSS</span>.</p>

Read the parts:

  • span — Groups a small piece of inline text so a class can color or highlight it. It does not add emphasis by itself.
  • em / strong — em expresses stress emphasis; strong expresses importance. This site styles em in a serif font, but that appearance is separate from its meaning.
  • small — Marks side text such as the layer descriptions. CSS can size text independently of this element.
  • b / i — b draws attention without extra importance; i marks alternate voice or similar text. Here they are reused inside decorative, aria-hidden artwork. Empty i elements become browser dots only because CSS gives them dimensions and a background.

Used here: Highlights, italic hero words, labels, layer captions, and decorative browser dots.

Landmarks: header, nav, main, section, article, aside, footer

header introduces a region; nav groups major navigation; main contains primary content. section groups a topic under a heading; article is a self-contained item; aside holds related supplementary content. footer contains supporting information. These meanings help readers and assistive technology understand the structure.

<section id="projects" aria-labelledby="projects-title">
  <h2 id="projects-title">Small pieces. Big possibilities.</h2>
  <article class="project-card">…</article>
</section>

Read the parts:

  • header / nav / main / footer — header introduces, nav groups navigation, main contains the page’s primary content, and footer provides supporting information. Their tags do not automatically create the site’s columns or colors.
  • section / article / aside — section groups a named topic; article represents a self-contained card; aside holds supplementary notes. Pick the element for its meaning, then style its class.
  • aria-labelledby="projects-title" — This points to the h2 with id="projects-title". The section’s accessible name becomes that heading’s text.

Used here: Page frame, project gallery, and learning notes.

Links: a, href, relative paths, and fragments

a creates a link. href="#contact" targets an id in this document; href="tutorial.html" loads a sibling document in the same tab; href="index.html#lesson-html" loads that file and targets its lesson. Native navigation updates history. CSS gives links their appearance; it does not load the next page.

<a class="lesson-next" href="html-glossary.html">click here to learn more</a>

Read the parts:

  • <a …> and </a> — The opening and closing anchor tags enclose the clickable text. href belongs in the opening tag.
  • href="html-glossary.html" — The browser resolves this filename from the current folder. It loads a new document using the normal link behavior.
  • class="lesson-next" — This selects presentation rules. Removing this class changes how the link looks; the href still controls where it goes.

Used here: Lesson footers, guide invitation, dictionary indexes, and return links.

Lists: ul, ol, and li

ul groups items without an essential order; ol expresses a sequence; li is an item in either list. CSS removes list markers from the homepage technology labels while the tutorial keeps numbered explanation lists.

<ol><li>Create index.html.</li><li>Add the document frame.</li></ol>

Read the parts:

  • ol / ul — ol means ordered list and usually shows numbers; ul means unordered list and usually shows bullets.
  • li — Each li is one item inside either kind of list. Both opening and closing tags keep the item’s boundaries clear.

Used here: Technology labels and tutorial explanations.

mailto:, query strings, and %20

A mailto destination asks the configured email app to create a draft. ? starts query parameters; subject= supplies the subject and %20 encodes a space. It does not send mail and may do nothing if no handler is configured.

<a href="mailto:hello@example.com?subject=Hello%20from%20your%20portfolio">hello@example.com</a>

Read the parts:

  • mailto:hello@example.com — The part before ? identifies the email action and recipient. It is not a website request.
  • ?subject=Hello%20from%20your%20portfolio — ? starts additional parameters; subject names the field; the text after = supplies its value. %20 is URL encoding for a space, not an HTML entity.
  • Visible link text — The text between the anchor tags is a label. Changing only that text does not change the actual recipient in href.

Used here: Contact card. Replace the demonstration address for your own portfolio.

Metadata: meta and title

charset="UTF-8" sets text encoding. name="viewport" with width=device-width and initial-scale=1.0 lets mobile browsers use the device width at normal initial zoom. name="description" provides a page summary; title labels its tab and history entry.

<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>HTML, decoded.</title>

Read the parts:

  • charset="UTF-8" — Tells the browser how the file’s bytes encode text. Save the actual file as UTF-8 too.
  • name="viewport" / content="…" — name identifies the metadata setting. content supplies its value: device-width uses the device width; initial-scale=1.0 starts at normal scale.
  • <title> — The text inside title labels the browser tab. It does not create the visible h1 heading in the page body.

Used here: The head of every document.

noscript

Displays fallback HTML when scripting is disabled or unsupported. Here it explains why interactive controls are unavailable; navigation and native disclosures still work.

<noscript><p>Enable JavaScript to try the counter.</p></noscript>

Read the parts:

  • <noscript> — Wraps fallback markup that is displayed when scripts are disabled or unsupported. It does not catch errors in a script that tried to run.
  • The nested p — The paragraph supplies a readable message. It does not enable scripting or make the counter function.

Used here: Homepage JavaScript lesson.

pre and code

pre preserves whitespace and line breaks. code identifies source text; inline code does not preserve spacing by itself. The stylesheet gives larger samples a dark background and horizontal scrolling. These elements display examples; they do not execute code.

<pre><code>let count = 0;</code></pre>

Read the parts:

  • <pre> — Keeps the sample’s line breaks and indentation. Long lines need the stylesheet’s overflow rule to scroll.
  • <code>let count = 0;</code> — Marks the inner text as source code. That JavaScript declaration is displayed here; it runs only when placed in an executing script.

Used here: The workbench, walkthrough, and dictionaries.

Resources: link, rel, script, src, and defer

link rel="stylesheet" imports CSS from href. script src imports JavaScript; defer downloads alongside parsing and executes after the document is parsed. Reading pages share the CSS but need no script. Relative filenames resolve from the document location.

<link rel="stylesheet" href="styles.css">
<script src="script.js" defer></script>

Read the parts:

  • link / rel / href — link declares a relationship to a resource. rel="stylesheet" identifies CSS; href gives its location. Unlike a, link does not create clickable page text.
  • script / src — script loads executable code from src. Keep the closing </script> even when its content comes from another file.
  • defer — Lets the browser finish parsing HTML before running this external classic script. That timing lets DOM queries find the page’s controls.

Used here: The homepage head; all other pages load only styles.css.

role and aria-current

role="img" presents the blueprint as one named illustration. role="group" labels related filter controls. role="status" marks a polite live update. aria-current="page" identifies the current document in navigation and is also a styling hook. Prefer native elements where they already supply the right role.

<a href="html-glossary.html" aria-current="page">HTML dictionary</a>

Read the parts:

  • role — Describes how assistive technology should interpret an element. An img role does not download an image; a group role does not create a visual border.
  • aria-current="page" — Says this link represents the current page. It is different from aria-pressed, which describes a toggle button’s state.
  • The anchor still uses href — aria-current names the current item; href remains the actual navigation destination.

Used here: Illustration, controls, counter, and learning-page navigation.

tabindex and keyboard focus

tabindex="0" includes an otherwise noninteractive element in normal keyboard tab order. On pre blocks it lets keyboard readers focus and scroll overflowing code. Native links, buttons, and summaries already support keyboard focus.

<pre tabindex="0" aria-label="Code example"><code>…</code></pre>

Read the parts:

  • tabindex="0" — Places this pre in normal sequential keyboard order. Zero does not mean “first”; its position follows document order.
  • aria-label="Code example" — Names the focused code panel. It does not display a visible heading above it.

Used here: Scrollable code samples.

Wrappers: div and class reuse

div groups block content without adding semantic meaning. Use it for layout within meaningful sections. Multiple space-separated classes combine reusable rules: section-wrap centers a section while another class supplies its specific layout.

<div class="hero-actions">…</div>

Read the parts:

  • div — A generic grouping element. Here it collects action links so CSS can lay them out as a row.
  • class="hero-actions" — This name matches .hero-actions in CSS. A class name can be chosen by the author; HTML does not know what “hero” means.
  • Multiple classes — class="hero section-wrap" applies both .hero and .section-wrap rules to the same element. The space separates two names.

Used here: Action rows, lesson columns, and CSS illustrations.
