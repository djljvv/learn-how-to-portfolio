Read a JavaScript statement from left to right

const button = document.querySelector("#counter-button");
  1. const declares a name; button is the name chosen by the author. = assigns the value produced by the expression on its right. The final semicolon ends the statement.
  2. document is supplied by the browser. The dot accesses its querySelector method. Parentheses call the method; the text between them is its argument.
  3. "#counter-button" is a string: quoted text. # belongs to the CSS selector inside that string. By contrast, button without quotes is a variable reference. Numbers such as 0 and booleans such as false are different value types.
  4. These examples use the homepage’s existing elements and variables. A fragment may need earlier declarations or an event callback; do not paste every dictionary example into one script. For complete working code, use steps 9 and 10 of the guide.

Assignment and increment: = and +=

= assigns a value; it does not compare two values. count += 1 is shorthand for count = count + 1. visibleCount uses the same operation for each card that matches a filter.

let count = 0;
count += 1;

Read the parts:

  • let count = 0; — let declares a variable, count names it, = assigns a value, and 0 is a number. The semicolon ends the statement.
  • count += 1; — Reads the current number, adds one, and stores the result back in count. After these two lines, count is 1; the page changes only when code writes that value into the DOM.

Used here: Counter and filter result count.

Blocks, calls, and arrow functions

Braces group statements into a block; parentheses call a function or list parameters. (card) => { … } creates an arrow function with a parameter, and () => { … } takes no named parameters. A callback is a function passed to another API to run later or for each item.

button.addEventListener("click", () => {
  count += 1;
});

Read the parts:

  • button.addEventListener — The dot accesses a method on the button object. The parentheses after the method name call it.
  • "click", () => { … } — The comma separates two arguments: an event-name string and a function. Empty parentheses mean the function declares no named parameters.
  • }); — The } closes the function body, ) closes the method call, and ; ends the statement. Leaving one out can cause a syntax error.

Used here: All event handlers and forEach callbacks.

classList.toggle()

classList exposes an element’s classes. toggle("notes-off") adds the class if absent or removes it if present, returning true when it is now present. The stylesheet reads that class to hide optional notes.

const notesAreOff = document.body.classList.toggle("notes-off");

Read the parts:

  • document.body.classList — Read left to right: the current document, its body element, then that element’s class collection.
  • toggle("notes-off") — The quoted string names a class. Do not include a dot here: this method takes a class name, unlike querySelector which takes a selector.
  • const notesAreOff = … — Saves the returned boolean. true means the class is now present, so the CSS hiding rule applies.

Used here: Learning-notes switch.

Comments: // and /* … */

// starts a comment through the end of the line; /* … */ encloses a block comment. Neither executes. Comments beside behavior explain why state, visibility, and accessibility change together.

// Reloading starts a new count.
let count = 0;

Read the parts:

  • // Reloading starts a new count. — This line is explanation. The browser does not interpret its words as instructions.
  • /* … */ — A block comment can span lines or sit inside a line. An ellipsis in an example usually marks omitted teaching code; it is not code to paste by itself.

Used here: Throughout script.js.

Conditionals: if, &&, and the ternary operator

if runs a block only for a truthy condition. && requires both operands to be truthy and short-circuits when the first is falsy. condition ? a : b chooses one of two values. The script checks element references before using them and chooses visible text using ternaries.

if (button && output) {
  button.hidden = false;
}
toggleState.textContent = notesAreOff ? "OFF" : "ON";

Read the parts:

  • if (button && output) — For these DOM references, the condition passes when both elements were found. A missing query returns null, which behaves as false in this test.
  • { button.hidden = false; } — The braces enclose the statements to run only when the condition passes. false is an unquoted boolean, not the string "false".
  • notesAreOff ? "OFF" : "ON" — Read as “if notesAreOff is true, choose OFF; otherwise choose ON.” The result is a string assigned to textContent.

Used here: Feature guards, notes state label, and filter status wording.

const, let, and scope

const declares a binding that cannot be reassigned; the referenced DOM element can still change. let permits reassignment. Both are block scoped. count lives in the counter’s feature block and its callback retains access to it; visibleCount starts fresh within every filter click.

const output = document.querySelector("#counter-output");
let count = 0;

Read the parts:

  • const output — Creates a name for the element reference. const prevents assigning output to another value; it still allows output.textContent to change.
  • let count — Creates a variable whose value can change. JavaScript treats count and Count as different names.
  • Scope — A name declared inside a block is available within that block and functions created there. The counter callback keeps access to count between clicks.

Used here: Element references and mutable counts.

dataset and data-* attributes

dataset exposes custom HTML data-* values as strings. data-filter becomes dataset.filter; data-category becomes dataset.category. These connect buttons to cards without depending on the words visible on the page.

const selectedCategory = filter.dataset.filter;
const category = card.dataset.category;

Read the parts:

  • filter.dataset.filter — The first filter is the variable holding a button; the last filter is the property corresponding to its data-filter attribute. Their repeated spelling does not make them the same thing.
  • card.dataset.category — Reads a string such as "html" from one article’s data-category. Custom HTML attributes beginning data- become properties of dataset.
  • const selectedCategory = … — Stores the selected button’s category for this click. It does not itself filter or hide anything.

Used here: Project gallery filter.

document, body, and the DOM

The browser parses HTML into a Document Object Model: objects representing elements and text. document is the current document; document.body is its body element. Changing these live objects updates the page, not the source file on disk.

document.body.classList.toggle("notes-off");

Read the parts:

  • document — A browser-provided object, not a variable you need to create. It represents the current loaded HTML document.
  • .body — A property that refers to the body element. Dots access properties or methods; they are not file-path separators.
  • toggle("notes-off") — Changes the live body’s class attribute. Inspect Elements to see that change; the saved index.html file does not change.

Used here: All homepage interactions.

Equality and logic: ===, ||, and !

=== compares without type conversion; for elements it checks whether references point to the same object. || means either condition may match. ! reverses truthiness. Thus the “all” filter accepts every card and card.hidden is the opposite of matches.

const matches = selectedCategory === "all" || card.dataset.category === selectedCategory;
card.hidden = !matches;

Read the parts:

  • === — Tests equality without converting types: the number 1 is not strictly equal to the string "1". Here both category values are strings.
  • || — Combines the two boolean comparisons: “all selected” OR “this category selected.” At least one must pass.
  • !matches — Negates the boolean. A matching card gets hidden = false, so it remains visible. For more general values, || and && return operands rather than always returning booleans.

Used here: Matching categories and marking the pressed filter.

Events: addEventListener("click", callback)

Registers a function to run when the element receives a click. Registering does not immediately run the function. Native buttons also produce clicks through keyboard activation. The callback updates local state; the page does not reload.

button.addEventListener("click", () => {
  count += 1;
  output.textContent = `Count: ${count}`;
});

Read the parts:

  • "click" — A string identifying which event to listen for. It must use the event’s recognized name; an arbitrary word will not respond to button clicks.
  • () => { … } — A function passed to addEventListener. Its body runs on each click, not while the listener is being registered.
  • count += 1 then output.textContent = … — First change the number, then render it into the output element. The example assumes button, output, and count have already been created.

Used here: Counter, filter buttons, and notes switch.

forEach() and NodeList

querySelectorAll returns a static NodeList of matches in document order. forEach invokes the callback once per item. The script loops once to attach listeners, then again during a click to update cards and pressed states. Later-added elements would need new queries and listeners.

filters.forEach((filter) => {
  filter.addEventListener("click", () => { /* update cards */ });
});

Read the parts:

  • filters — A NodeList of buttons returned by querySelectorAll. It holds several elements, unlike the single element returned by querySelector.
  • (filter) => — Names the current item for one callback invocation. The callback runs again with the next button until the collection is exhausted.
  • The inner click callback — Attaches behavior to that particular button. The outer loop runs during setup; the inner callback waits for user interaction.

Used here: Project filter setup and updates.

hidden property

A boolean DOM property reflecting the HTML hidden attribute. true hides; false reveals. Cards remain in the document and can be shown again. Hidden content is removed from layout and accessibility exposure.

filterBar.hidden = false;
card.hidden = !matches;

Read the parts:

  • filterBar.hidden = false — Reveals the filter bar. false is a boolean literal with no quotation marks.
  • card.hidden = !matches — Sets visibility for each card according to the comparison result. This hides the existing card rather than deleting it.

Used here: Progressively revealed controls and filtered cards.

In-memory state and progressive enhancement

count and DOM changes exist only in the loaded page; the script uses no persistent storage. Reload initializes defaults, while browser Back can restore a cached document. Controls start hidden and are revealed only where their elements exist. Static reading pages require no script.

let count = 0;
button.hidden = false;

Read the parts:

  • let count = 0 — Initializes a fresh counter whenever this script starts for a new document load. It is not a database field.
  • button.hidden = false — Enhances the static page by revealing a working control. If JavaScript is disabled, the original hidden attribute remains.

Used here: The homepage’s optional interaction layer.

null and missing-element guards

querySelector returns null when nothing matches. Accessing a property of null would throw an error. The finished script checks required elements before initialization, allowing each feature to be removed from HTML without breaking the others. An empty NodeList is safe to iterate.

const button = document.querySelector("#counter-button");
const output = document.querySelector("#counter-output");
if (button && output) {
  // Initialize only when both elements are present.
}

Read the parts:

  • null — An explicit “no value” result here. It is not the quoted word "null", an empty string, or zero.
  • if (button && output) — Checks that both references exist before the code tries to use their properties. An empty querySelectorAll result is a collection with zero items, not null.

Used here: The three guarded feature blocks in script.js.

querySelector() and querySelectorAll()

querySelector returns the first matching element or null; querySelectorAll returns every match as a NodeList. Arguments use CSS selector syntax. Calling querySelector on notesToggle restricts the search to its descendants.

const notesToggle = document.querySelector(".notes-toggle");
const filters = document.querySelectorAll("[data-filter]");

Read the parts:

  • ".notes-toggle" — A CSS class selector passed as a JavaScript string. The dot is inside the quotes because it is part of the selector.
  • "[data-filter]" — An attribute selector matching elements with data-filter. The square brackets are selector text, not a JavaScript array in this context.
  • querySelectorAll versus querySelector — All returns a collection, even for one match; the singular method returns one element or null. Choose the API according to whether you need a group or one target.

Used here: Element lookup at the start of each feature.

setAttribute() and String()

setAttribute writes a named HTML attribute. String() explicitly converts a boolean into "true" or "false" for aria-pressed. Attribute values communicate state; CSS attribute selectors also use the same value for appearance.

button.setAttribute("aria-pressed", String(button === filter));

Read the parts:

  • "aria-pressed" — The name of the HTML attribute to write. The hyphen belongs in the string; it is not subtraction.
  • button === filter — Compares two element references. It is true only for the button that is the current selected filter.
  • String(…) — Converts that boolean into the attribute text "true" or "false". setAttribute receives the name as its first argument and that text as its second.

Used here: Filter selection and learning-notes state.

Strict mode: "use strict"

This directive enables stricter JavaScript rules in this classic script, helping catch mistakes such as assigning to an undeclared variable. It belongs before executable statements; comments may appear before it.

"use strict";

Read the parts:

  • "use strict"; — A special string-literal directive when placed at the start of this script. The exact words opt into strict mode.
  • The quotation marks — Delimit the directive string; they are code syntax and do not appear on the page. Ordinary standalone strings later in a script would not enable this mode.

Used here: First statement in script.js.

Template literals: backticks and ${…}

Backticks create a template literal. ${expression} inserts an evaluated value into the text. Filter status uses a nested conditional expression to add “s” only when the count is not one.

output.textContent = `Count: ${count}`;
const noun = `example${visibleCount === 1 ? "" : "s"}`;

Read the parts:

  • `Count: ${count}` — Backticks allow interpolation. If count is 2, the resulting string is "Count: 2". Single or double quotes would leave ${count} as literal text.
  • visibleCount === 1 ? "" : "s" — Chooses an empty string for one item or the letter s for other counts. Combined with example, that produces example or examples.
  • const noun — Stores the constructed word in this explanatory example. It is not shown on the page unless another statement writes it to an element.

Used here: Counter output and filter announcements.

textContent

Reads or replaces an element’s text. Setting it does not interpret the value as HTML. Replacing the contents also removes any existing child markup, so this site targets simple output and label elements.

toggleState.textContent = notesAreOff ? "OFF" : "ON";

Read the parts:

  • toggleState — The variable referring to the small ON/OFF span inside the notes button. It must be queried before this assignment runs.
  • .textContent = … — Replaces that element’s contents with text. A value such as "<b>ON</b>" would display the tag characters rather than creating bold markup.

Used here: State label, counter, and filter status.

trim()

Returns a string with whitespace removed from its beginning and end, leaving the original string unchanged. The filter’s visible label becomes clean text for the result message.

filter.textContent.trim();

Read the parts:

  • filter.textContent — Reads the button’s current text as a string, including surrounding whitespace from formatting.
  • .trim() — Calls a string method. For " CSS ", the returned value is "CSS". This call alone does not rewrite the button label; the full script uses the returned string in the status message.

Used here: Category-specific filter announcements.
