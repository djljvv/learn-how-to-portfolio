STEP 01 / 12

Start with three files

Create a folder with index.html, styles.css, and script.js in a text editor. The first holds content, the second styles it, and the third supplies interactions. Open index.html in your browser; save edits and reload to see them. There is no installation or build command.

portfolio/
  index.html
  styles.css
  script.js
  1. Begin with the HTML document in step 2. Add the later examples inside its body or to the named CSS and JavaScript files.
  2. These snippets teach one feature at a time; they are excerpts, not a complete copy-and-paste website. For the exact finished implementation, open the three files from this repository in your editor.
  3. Use browser developer tools: Elements shows the live document and styles; Console shows JavaScript errors. View Page Source shows the original HTML, before JavaScript changes it.

What you should see: You can work locally. The finished site also works on a static host that serves these files together.

STEP 02 / 12

Give the browser a document

Start index.html with this outer frame. HTML tags usually come in opening and closing pairs; attributes inside the opening tag configure the element.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Portfolio, explained</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <main id="main">Hello, website.</main>
</body>
</html>
  1. DOCTYPE selects modern standards mode. html wraps the document; lang identifies English for assistive technology.
  2. head holds metadata. charset preserves punctuation, viewport lets phone layouts use the device width, and title labels the browser tab. The finished page also has a description meta tag.
  3. link loads CSS from the same folder. script loads JavaScript; defer waits until HTML parsing finishes before running it.
  4. body contains visible content. main marks the primary content, and id="main" gives it a unique destination. Closing tags end each region.

What you should see: The browser displays “Hello, website.” Styling and behavior can now be added independently.

STEP 03 / 12

Map the portfolio into meaningful sections

The homepage is organized into a header, a main region, and a footer. Inside main, each section has a heading and an id. Build the content before worrying about its appearance.

<a class="skip-link" href="#main">Skip to content</a>
<header class="site-header">
  <nav aria-label="Main navigation">
    <a href="#about">About</a>
  </nav>
</header>
<main id="main">
  <section id="about" aria-labelledby="about-title">
    <h2 id="about-title">A little about this person.</h2>
    <p>Meet the three things that make this page work.</p>
  </section>
</main>
<footer>Built with curiosity.</footer>
  1. The skip link is first in keyboard order. CSS reveals it on focus so readers can bypass repeated navigation.
  2. header introduces the site; nav groups navigation links. aria-label gives that navigation a descriptive name.
  3. href="#about" moves within the current document to id="about". aria-labelledby names the section using the text of its heading.
  4. The actual homepage adds a hero with one h1, About, Projects, the code workbench, the build-guide invitation, and Contact. h2 introduces sections; h3 introduces cards. Lists group related technology labels.

What you should see: Content has a readable order even without CSS. Try Tab, then Enter on the skip link.

STEP 04 / 12

Set the visual language once

Put shared choices at the top of styles.css. The warm paper background, green accents, dark ink, serif emphasis, and monospace labels are the visual vocabulary reused by every page.

:root {
  --paper: #faf9f6;
  --ink: #272b25;
  --green: #d9e8cb;
}
*, *::before, *::after { box-sizing: border-box; }
body {
  margin: 0;
  background: var(--paper);
  color: var(--ink);
  font-family: "Segoe UI", Arial, sans-serif;
  line-height: 1.65;
}
.section-wrap {
  width: min(1180px, calc(100% - 88px));
  margin-inline: auto;
}
  1. A selector chooses elements; braces contain property: value declarations separated by semicolons. :root stores custom properties; var() reads them.
  2. The universal selector and the two pseudo-elements share border-box sizing, so borders and padding fit inside declared widths.
  3. body removes the default outer margin and sets inherited text styling. Font fallbacks avoid needing an external font download.
  4. min() caps the wrapper at 1180px. calc() reserves 44px on each side; auto inline margins center the wrapper. clamp() elsewhere scales headings between lower and upper limits.

What you should see: Changing --paper updates every place that uses that variable. Some illustration colors are separate literal values.

STEP 05 / 12

Arrange the hero, gallery, and illustrations

CSS Grid handles major columns; Flexbox aligns smaller rows such as navigation and buttons. The decorative artwork is HTML styled with CSS, so no image files are needed.

.project-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}
.project-card { min-width: 0; }
.hero-actions {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 24px;
}
.layer { position: absolute; transform: rotate(-7deg) skewX(-7deg); }
  1. display: grid establishes a grid. repeat(3, 1fr) creates three equal tracks; gap separates them. min-width: 0 lets cards shrink with their container.
  2. The hero uses proportional minmax(0, …) columns. About and Contact use two-column grids. .hero-foot spans from the first to the last grid line.
  3. Flexbox aligns link and button rows; flex-wrap lets them continue on another line when space runs out.
  4. The blueprint has position: relative, which contains absolutely positioned layers. Two linear gradients make graph paper; transform tilts cards; border-radius and box-shadow soften their edges.
  5. The gallery illustrations reuse those ideas: a miniature browser, overlapping color swatches, and a drawn button. aria-hidden excludes decorative artwork; the hero illustration has a single accessible name instead.

What you should see: Three gallery cards sit side by side on a wide screen. Hovering a real .button lifts it slightly using transform and transition.

STEP 06 / 12

Give each project card a category and destination

Build the gallery content inside the project grid. Each card is an article with a category stored in HTML; the filter buttons use matching values. The labels shown to the reader can change without changing those category keys.

<div class="filter-bar" hidden role="group" aria-label="Filter examples by technology">
  <button type="button" data-filter="all" aria-pressed="true">All examples</button>
  <button type="button" data-filter="html" aria-pressed="false">HTML</button>
</div>
<div class="project-grid">
  <article class="project-card" data-category="html">
    <div class="card-content">
      <h3>A place for everything.</h3>
      <p>Headings, sections, and links give a page its meaning.</p>
      <a class="card-link" href="#lesson-html">Explore the structure</a>
    </div>
  </article>
</div>
<p class="filter-status" aria-live="polite" aria-atomic="true">Showing all 3 examples.</p>
  1. article makes the card a self-contained example. class="project-card" connects it to CSS and the script; data-category="html" stores the category used by the filter.
  2. Repeat the card for css and js, with the corresponding headings, descriptions, and #lesson-css or #lesson-js links. Add matching CSS and JavaScript filter buttons too. The “3 examples” status describes that completed gallery.
  3. The finished cards place their decorative .project-art before .card-content. Keeping artwork separate from the text makes both layout and the accessible reading order easier to understand.
  4. The filter bar starts hidden because its buttons require JavaScript. aria-pressed="true" marks All as the initial selection. The cards themselves start visible, so the gallery still works without scripting.
  5. The status paragraph is separate from the cards. Its live-region attributes announce a changed result count while focus stays on the filter button. Step 10 supplies the behavior.

What you should see: With all three articles added, the gallery displays three examples. Each card link goes to its matching code lesson further down the homepage.

STEP 07 / 12

Make the page adapt and remain usable

Add media queries after the base styles. They override earlier declarations when their conditions match. Responsive design changes layout; accessibility also needs semantic HTML, visible focus, and understandable controls.

@media (max-width: 760px) {
  .project-grid { grid-template-columns: 1fr; }
  .lesson-body { grid-template-columns: 1fr; }
}
:focus-visible { outline: 3px solid #5e713f; outline-offset: 5px; }
[hidden] { display: none !important; }
@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
  .button { transition: none; }
  .button:hover { transform: none; }
}
  1. At 1000px and narrower, the original CSS tightens spacing. At 760px and narrower, the main grids stack, navigation wraps, and decorative file tags disappear.
  2. The focus outline shows keyboard users where they are. The hidden rule prevents display: grid or flex from making hidden elements visible again.
  3. Reduced-motion styles remove smooth scrolling and button animation when the operating system requests less motion.
  4. pre preserves code whitespace. overflow-x: auto keeps long lines inside a scrollable code block; the learning pages add tabindex="0" so keyboard readers can focus and scroll examples.

What you should see: Resize to a phone width, use Tab throughout the page, and try the system reduced-motion setting.

STEP 08 / 12

Build the expandable code lessons

Use native details and summary elements for the “Meet the code” boxes. Put prose beside a code sample and finish each box with a link to its language dictionary.

<details class="code-lesson" open>
  <summary>HTML gives things meaning</summary>
  <div class="lesson-body">
    <div><p>A link has a destination.</p></div>
    <pre><code>&lt;a href="#contact"&gt;Contact&lt;/a&gt;</code></pre>
  </div>
  <a class="lesson-next" href="html-glossary.html">click here to learn more</a>
</details>
  1. details owns the expanded state. open makes it expanded initially; summary is the keyboard-operable heading.
  2. The two-column .lesson-body reuses the page’s grid pattern and stacks on phones.
  3. pre retains spaces and newlines; code identifies source text. &lt; and &gt; display angle brackets instead of creating HTML elements. To show an ampersand itself, use &amp;.
  4. The glossary link is inside details, after the lesson body, so it appears at the bottom of the expanded box. Navigation remains a link even when styled like a button.

What you should see: Activate a lesson heading to collapse or expand it. This works with JavaScript disabled.

STEP 09 / 12

Connect one click to one update

Add the counter markup to HTML and the event listener to script.js. This is the smallest version of the same find → listen → update pattern used by the other controls.

<button type="button" id="counter-button" hidden>Try a click</button>
<p id="counter-output" role="status">Count: 0</p>

// In script.js, after the HTML has been parsed:
const button = document.querySelector("#counter-button");
const output = document.querySelector("#counter-output");
let count = 0;
button.hidden = false;
button.addEventListener("click", () => {
  count += 1;
  output.textContent = `Count: ${count}`;
});
  1. Keep the HTML and JavaScript portions in their respective files. The button starts hidden until its handler can be initialized; type="button" prevents accidental form submission if it is later placed inside a form.
  2. querySelector finds the first matching element. const keeps the element reference; let allows count to change. The finished shared script checks that both elements exist before using them.
  3. hidden = false reveals the control. addEventListener registers a callback rather than running it immediately. Each click adds one to count.
  4. The backtick string inserts count using ${…}. textContent writes text rather than HTML. role="status" politely announces the changed output without moving focus.

What you should see: The homepage counter increases by one per click. A fresh load starts at zero; there is no saved counter.

STEP 10 / 12

Filter cards and toggle learning notes

The gallery stores categories in data-* attributes. JavaScript compares each category to the selected filter, updates hidden, and announces the visible count. The notes switch uses the same event pattern to add or remove one CSS class.

// Inside a filter click callback:
const selectedCategory = filter.dataset.filter;
let visibleCount = 0;
cards.forEach((card) => {
  const matches = selectedCategory === "all" || card.dataset.category === selectedCategory;
  card.hidden = !matches;
  if (matches) visibleCount += 1;
});

// Inside the notes click callback:
const notesAreOff = document.body.classList.toggle("notes-off");
notesToggle.setAttribute("aria-pressed", String(!notesAreOff));
toggleState.textContent = notesAreOff ? "OFF" : "ON";
  1. querySelectorAll collects filter buttons and project cards. forEach attaches a click callback to each filter and later visits every card.
  2. dataset.filter reads data-filter; dataset.category reads data-category. === tests equality, || accepts either condition, and ! reverses the boolean. “all” matches every card.
  3. Only matching cards stay visible. The script sets aria-pressed on each filter so exactly the selected button is pressed, then writes the count into the polite live status. trim() removes surrounding whitespace from the filter label; a conditional adds the plural “s” when needed.
  4. classList.toggle returns whether notes-off is now present. CSS .notes-off .learning-note hides only optional annotations. String(!notesAreOff) communicates the inverse as aria-pressed; the conditional operator chooses OFF or ON.
  5. The final script guards each feature with if so a missing control does not stop other features. New reading pages do not load it because their navigation and disclosure elements need no JavaScript.

What you should see: Choose CSS to see one card, then All to restore three. Turn notes off: essential content, glossary links, and the build guide remain available.

STEP 11 / 12

Open a new page and explain the transition

Create tutorial.html, html-glossary.html, css-glossary.html, and javascript-glossary.html beside index.html. Each is a full HTML document with its own title, main content, and the same stylesheet link. The homepage’s new build-guide section links here.

<!-- On index.html: a different document in the same folder. -->
<a href="tutorial.html">Build the site, step by step</a>

<!-- On a glossary page: a document plus a section within it. -->
<a href="index.html#lesson-html">Back to the HTML example</a>

<!-- In the head of every learning page: -->
<link rel="stylesheet" href="styles.css">
  1. When you activate the first link, the browser resolves tutorial.html relative to the current document’s folder, loads that document, and displays it in the same tab. There is no target="_blank" and no JavaScript router.
  2. On a hosted site the browser requests that file from the server; when opened locally it reads a sibling file. It parses the new HTML and applies styles.css, potentially reusing a cached copy.
  3. The URL changes and the previous page is added to browser history. Back returns to it. A filename plus #lesson-html loads the homepage and targets that lesson. A bare #id stays in the current document.
  4. The shared stylesheet makes the new page feel continuous with the original. CSS transition only animates button styling here; it does not animate the change between documents.
  5. A new document initializes its own script state if it loads a script. Reloading the homepage resets the counter and notes; Back may restore earlier state through the browser’s page cache. Nothing is written to localStorage.

What you should see: Use the back-to-example links and browser Back. Navigation, glossaries, and this entire guide remain usable without JavaScript.

STEP 12 / 12

Finish the contact section and verify the site

The contact card demonstrates an email link. Finish with the footer, then check both the visual result and the behavior of every control before sharing the folder through a static host.

<a href="mailto:hello@example.com?subject=Hello%20from%20your%20portfolio">
  hello@example.com
</a>
  1. mailto: asks the configured email handler to open a draft. ?subject= supplies a subject, and %20 encodes a space. This does not send a message; example.com is a demonstration address.
  2. Read through at wide and narrow widths. Confirm there is no page-wide horizontal scroll and that code blocks scroll independently.
  3. Test each filter, the counter, notes, lesson disclosures, same-page links, all four new page destinations, and return links. Check keyboard focus and the developer console.
  4. Disable JavaScript and reload: content, navigation, and details remain available; JavaScript-only controls stay hidden. Re-enable it and reload for the interactive examples.
  5. Keep the files together with the same relative names when hosting. There is no form backend, analytics service, framework, or persistent user data in this project.

What you should see: You have the complete structure → style → behavior → navigation workflow. Use the three dictionaries above to look up individual features.
