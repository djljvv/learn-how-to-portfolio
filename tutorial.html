STEP 00 / BEFORE YOU START

Get ready to build.

You need a desktop or laptop, a browser, and a plain-text code editor. You only need to know how to make folders, save files, and copy text. HTML, CSS, and JavaScript are explained as you go. Git is optional for recording checkpoints; no Node.js, package manager, account, or web server is needed to run the site.

  1. Download or clone this repository and keep it as your reference folder. Open its tutorial.html in a browser and its files in your editor. Create a separate, empty folder named portfolio-practice alongside it; this is where you build.
  2. Show filename extensions in your file manager. Save files as plain text with UTF-8 encoding. index.html.txt will not work as index.html. Keep filenames lowercase and use straight code quotes, not typographic quotation marks.
  3. Create means make a new file. Replace means remove the specified old content and put the new content in the same place. Append means add after the existing content. Do not paste a second document, a second main, or a duplicate script into the file.
  4. The small snippets explain a feature. Boxes marked Complete code to copy contain the actual code for that operation. Copy their displayed code into the named file, not the surrounding explanation. A sample containing … is abbreviated and is not a complete implementation.
  5. Save in the editor, open your practice folder’s index.html, and reload after each change. Keep the guide and your practice page in separate tabs and check the address bar before testing. Open developer tools with F12 or your browser menu and check Console for errors.
  6. If you want commits, install Git and run git --version in a terminal. Open that terminal in portfolio-practice. Run git init once if it is not already a repository. If Git asks for an identity, set your name and email with git config user.name "Your Name" and git config user.email "you@example.com", replacing those example values. These settings apply to this repository.

How a checkpoint works

Save → reload → run the listed checks → inspect your changes → commit only if the checks pass. Git commands go in your terminal, never in HTML, CSS, JavaScript, or the browser console. A commit is a local snapshot; it does not publish or upload the site.

git status
git diff
git add index.html styles.css script.js
git diff --cached
git commit -m "created page structure"

status lists changed and untracked files. diff shows edits to tracked files; open new files in the editor to review them. add stages the named files, diff --cached reviews that staged snapshot, and commit -m saves it with a message. At later checkpoints, use the message shown there. If a check fails, fix it and repeat the check before saving a milestone.

Without Git, copy the whole practice folder to a new folder such as portfolio-after-step-03 after a successful check. The supplied structure, responsive layout, and interaction checkpoints are working comparisons. Open them in place, or copy their three files into a separate comparison folder; keep your own work to compare changes.

Ready when: Your reference page is open, your empty practice folder is open in an editor, and you can distinguish the editor, browser, and optional terminal.

STEP 02 / 12

Give the browser a document

Start index.html with this outer frame. HTML tags usually come in opening and closing pairs; attributes inside the opening tag configure the element.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Portfolio, explained</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <main id="main">Hello, website.</main>
</body>
</html>
  1. DOCTYPE selects modern standards mode. html wraps the document; lang identifies English for assistive technology.
  2. head holds metadata. charset preserves punctuation, viewport lets phone layouts use the device width, and title labels the browser tab. The finished page also has a description meta tag.
  3. link loads CSS from the same folder. script loads JavaScript; defer waits until HTML parsing finishes before running it.
  4. body contains visible content. main marks the primary content, and id="main" gives it a unique destination. Closing tags end each region.

What you should see: The browser displays “Hello, website.” Styling and behavior can now be added independently.

Replace index.html

  1. Copy the complete document example above, starting at <!DOCTYPE html> and ending at </html>, into index.html. Save the file.
  2. Double-click this practice file to open it. Check that the tab title is “Portfolio, explained” and the page says “Hello, website.” The two linked files exist but are still empty.

Run the document

  1. The browser tab shows your title and the page displays “Hello, website.”
  2. If it is blank, check that you saved the right file and did not save it with a .txt extension.

If it works, commit: review the changed files, stage them, then run the command below in your practice terminal. If it fails, fix and retest first.

STEP 04 / 12

Set the visual language once

Put shared choices at the top of styles.css. The warm paper background, green accents, dark ink, serif emphasis, and monospace labels are the visual vocabulary reused by every page.

:root {
  --paper: #faf9f6;
  --ink: #272b25;
  --green: #d9e8cb;
}
*, *::before, *::after { box-sizing: border-box; }
body {
  margin: 0;
  background: var(--paper);
  color: var(--ink);
  font-family: "Segoe UI", Arial, sans-serif;
  line-height: 1.65;
}
.section-wrap {
  width: min(1180px, calc(100% - 88px));
  margin-inline: auto;
}
  1. A selector chooses elements; braces contain property: value declarations separated by semicolons. :root stores custom properties; var() reads them.
  2. The universal selector and the two pseudo-elements share border-box sizing, so borders and padding fit inside declared widths.
  3. body removes the default outer margin and sets inherited text styling. Font fallbacks avoid needing an external font download.
  4. min() caps the wrapper at 1180px. calc() reserves 44px on each side; auto inline margins center the wrapper. clamp() elsewhere scales headings between lower and upper limits.

What you should see: Changing --paper updates every place that uses that variable. Some illustration colors are separate literal values.

STEP 05 / 12

Arrange the hero, gallery, and illustrations

CSS Grid handles major columns; Flexbox aligns smaller rows such as navigation and buttons. The decorative artwork is HTML styled with CSS, so no image files are needed.

.project-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}
.project-card { min-width: 0; }
.hero-actions {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 24px;
}
.layer { position: absolute; transform: rotate(-7deg) skewX(-7deg); }
  1. display: grid establishes a grid. repeat(3, 1fr) creates three equal tracks; gap separates them. min-width: 0 lets cards shrink with their container.
  2. The hero uses proportional minmax(0, …) columns. About and Contact use two-column grids. .hero-foot spans from the first to the last grid line.
  3. Flexbox aligns link and button rows; flex-wrap lets them continue on another line when space runs out.
  4. The blueprint has position: relative, which contains absolutely positioned layers. Two linear gradients make graph paper; transform tilts cards; border-radius and box-shadow soften their edges.
  5. The gallery illustrations reuse those ideas: a miniature browser, overlapping color swatches, and a drawn button. aria-hidden excludes decorative artwork; the hero illustration has a single accessible name instead.

What you should see: The hero has two columns on a wide screen and its three layers tilt. Buttons lift slightly on hover. The gallery cards are added in step 6.

/* JavaScript is the behavior layer. This script uses browser APIs only—no libraries.
   index.html loads it with defer, so HTML parsing finishes before we query elements.
   Each feature checks its required elements so deleting one demo cannot break another.
   The reading pages use native HTML navigation and do not need this script.
   const declares a binding we won't reassign; let declares one that can change. */
'use strict';

// 1. LEARNING NOTES: querySelector returns the first element matching a CSS selector.
const notesToggle = document.querySelector('.notes-toggle');
// querySelector returns null if markup is absent. Check the parent before querying inside it.
const toggleState = notesToggle ? notesToggle.querySelector('.toggle-state') : null;

// Initialize only when this feature's required markup exists.
if (notesToggle && toggleState) {
  // Reveal the control now that its behavior is available. Without JS, notes remain visible.
  notesToggle.hidden = false;
  notesToggle.addEventListener('click', () => {
    // classList.toggle adds a missing class or removes an existing one.
    // It returns true when the class is now present. CSS hides notes when notes-off is present.
    const notesAreOff = document.body.classList.toggle('notes-off');
    // aria-pressed communicates button state to assistive technology; ! reverses a boolean.
    notesToggle.setAttribute('aria-pressed', String(!notesAreOff));
    toggleState.textContent = notesAreOff ? 'OFF' : 'ON';
  });
}

// 2. PROJECT FILTERS: querySelectorAll gives us all matches, not just the first.
const filterBar = document.querySelector('.filter-bar');
const filters = document.querySelectorAll('[data-filter]');
const cards = document.querySelectorAll('.project-card');
const filterStatus = document.querySelector('.filter-status');
// Initialize only when this feature's required markup exists.
if (filterBar && filterStatus) {
  filterBar.hidden = false;

  // forEach runs a function for each item. Each button gets its own click listener.
  filters.forEach((filter) => {
    filter.addEventListener('click', () => {
      // dataset exposes HTML data-* attributes: data-filter becomes dataset.filter.
      const selectedCategory = filter.dataset.filter;
      let visibleCount = 0;

      cards.forEach((card) => {
        // || means OR; === compares exact values. "all" matches every category.
        const matches = selectedCategory === 'all' || card.dataset.category === selectedCategory;
        // hidden removes a card from layout AND from the accessibility tree.
        card.hidden = !matches;
        if (matches) visibleCount += 1;
      });

      // Only the selected filter is pressed. Focus stays on the button you activated.
      filters.forEach((button) => {
        button.setAttribute('aria-pressed', String(button === filter));
      });

      // textContent writes text safely, without interpreting it as HTML.
      // Backticks create a template literal; ${...} inserts an expression into it.
      filterStatus.textContent = selectedCategory === 'all'
        ? `Showing all ${visibleCount} examples.`
        : `Showing ${visibleCount} ${filter.textContent.trim()} example${visibleCount === 1 ? '' : 's'}.`;
    });
  });
}
