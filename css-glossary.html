Read a CSS rule from left to right

.project-grid { display: grid; gap: 24px; }
  1. .project-grid is the selector: choose elements whose HTML class includes project-grid. The leading dot means class; it is not written in the class attribute value.
  2. The braces enclose declarations. display and gap are property names. A colon introduces a value; a semicolon ends one declaration. grid is a keyword, and 24px is a number with a unit.
  3. Each declaration changes one aspect of the selected element. CSS goes into styles.css here, without HTML style tags. A selector with no matching element has no visible effect.
  4. The definitions below distinguish closely related properties. Try one value at a time in the practice page, save, and reload to connect that value to its result.

Alignment: align-items, align-self, justify-content, justify-self

These align children or an individual item within flex or grid layout. center centers; space-between distributes free space between items; start and end align to edges. The header uses space-between; the phone blueprint uses justify-self: center.

.site-header { display: flex; align-items: center; justify-content: space-between; }

Read the parts:

  • align-items / align-self — align-items sets alignment for the container’s items; align-self overrides it for one item. In a default flex row, this is the vertical cross axis.
  • justify-content / justify-self — justify-content distributes or aligns the group along the main axis in flex, or the grid tracks in grid. justify-self aligns one grid item within its area; it does not align individual flex items.
  • space-between — The first and last items touch opposite available edges, with the free space between items. With only one item there are no between-item gaps to distribute.

Used here: Header, hero artwork, buttons, and footer.

background, background-color, background-image, background-size

background is shorthand for background properties. A color paints the element; linear-gradient() creates an image without a file. Two perpendicular gradients draw graph-paper lines, and background-size controls their repeating tile size.

.blueprint {
  background-color: #eff1e8;
  background-image: linear-gradient(#dce2d350 1px, transparent 1px), linear-gradient(90deg, #dce2d350 1px, transparent 1px);
  background-size: 23px 23px;
}

Read the parts:

  • background-color / background-image — The color paints the base; images or gradients paint above it. The comma between two gradients makes two background layers.
  • linear-gradient(… 1px, transparent 1px) — The color occupies a thin line; transparent leaves the rest clear. 90deg turns the second gradient so the two directions cross.
  • background-size: 23px 23px — Sets each repeating background tile’s width and height. Smaller values make the graph-paper squares smaller.

Used here: Hero blueprint and card artwork.

border, border-radius, and box-shadow

border combines width, style, and color. border-top, border-bottom, border-left, border-block, and border-bottom-width target edges or subproperties. border-radius rounds corners; 50% makes equal-sized dots circular. box-shadow supplies offset, blur, and color; a zero blur makes a hard shadow.

.project-card { border: 1px solid var(--line); border-radius: 7px; }

Read the parts:

  • border: 1px solid var(--line) — The three parts mean line width, line style, and line color. A border occupies space inside border-box dimensions.
  • border-radius: 7px — Rounds each corner. This is a length, not a seven-percent roundness setting.
  • box-shadow: 8px 10px 0 #abb59d35 — Moves the shadow right by 8px and down by 10px, uses no blur, and supplies a transparent color. Unlike a border, the shadow does not take up layout space.

Used here: Cards, separators, pills, and layered artwork.

box-sizing: border-box

With border-box, declared width and height include padding and borders. Margin remains outside. The universal selector and pseudo-elements apply the rule consistently throughout the site.

*, *::before, *::after { box-sizing: border-box; }

Read the parts:

  • * — The universal selector matches every element. The comma adds ::before and ::after generated boxes to the same rule.
  • border-box — For a declared width of 200px and 20px padding on each side, the padding fits inside the 200px. Margin remains outside.

Used here: Global reset at the top of styles.css.

Cascade, inheritance, and !important

Rules can combine on one element. Among normal author rules, more specific selectors win; equally specific later rules override earlier ones. Some values, such as color, inherit. !important raises a declaration’s priority: this site uses it sparingly to enforce hidden state and small text overrides.

[hidden] { display: none !important; }
button { font: inherit; }

Read the parts:

  • [hidden] — The brackets select an attribute, not a class named hidden. It matches any element with that attribute present.
  • !important — Changes cascade priority for that declaration. It is used here so later display rules cannot accidentally reveal hidden controls.
  • font: inherit — The keyword inherit takes the parent’s computed font settings. Without this rule, browser defaults can make button text differ from nearby prose.

Used here: Global defaults, hidden controls, and responsive overrides.

color and color values

color sets foreground text and usually icon text. Hex colors use #RRGGBB; eight digits add alpha transparency. Named white and transparent are also used. inherit takes the parent’s computed value.

a { color: inherit; }
.code-comment { color: #b2c39b; }

Read the parts:

  • color versus background — color changes the foreground text. background paints behind the text; changing one does not automatically adjust the other.
  • #b2c39b — Six hexadecimal digits describe red, green, and blue. Eight-digit values add alpha; transparent means fully transparent.
  • inherit — The anchor uses the computed text color of its parent, keeping it in the site’s palette.

Used here: Text, links, code comments, and translucent shadows.

Comments and declaration syntax

/* … */ is a CSS comment. A rule pairs a selector with declarations in braces. Each declaration uses property: value; punctuation separates values and rules. Comma-separated selectors share declarations.

/* A period selects a class. */
.hero, .workbench { color: var(--ink); }

Read the parts:

  • .hero, .workbench — The comma means either selector can match. Without a comma, .hero .workbench would mean a workbench inside a hero.
  • { color: var(--ink); } — Braces surround the declarations; the colon separates a property from its value; the semicolon ends the declaration.
  • /* … */ — Comment punctuation is different from HTML’s <!-- … -->. Use the form for the language of the file you are editing.

Used here: Every section of styles.css.

cursor, touch-action, and tap highlight

cursor: pointer signals an actionable control. touch-action: manipulation supports panning and pinch zoom while discouraging double-tap zoom gestures. -webkit-tap-highlight-color is a browser-specific cosmetic setting; keyboard focus is handled separately with an outline.

button { cursor: pointer; }
button, a, summary { touch-action: manipulation; }
button, a { -webkit-tap-highlight-color: transparent; }

Read the parts:

  • cursor: pointer — Changes the pointer’s appearance while over the element. It does not create click behavior.
  • touch-action: manipulation — Allows scrolling and pinch zoom while limiting extra gesture handling such as double-tap zoom in supporting browsers.
  • -webkit-tap-highlight-color — A browser-prefixed cosmetic property for touch highlighting. Transparent removes that highlight; the separate focus outline still serves keyboard users.

Used here: Global interaction styles.

Custom properties: :root, --name, and var()

:root selects the document root. Names beginning -- store reusable values inherited by descendants; var(--name) inserts a value. The page uses theme colors and a monospace font stack this way.

:root { --green: #d9e8cb; }
.demo-button { background: var(--green); }

Read the parts:

  • :root — A built-in pseudo-class selecting the document root. Its single colon is selector syntax, different from the colon inside a declaration.
  • --green: #d9e8cb — Declares a custom property with an author-chosen name. The two leading hyphens are required.
  • var(--green) — Reads that stored value. It is not the literal word green and does not call JavaScript.

Used here: Theme tokens at the start of styles.css.

display: block, inline-block, flex, grid, and none

block creates a block box; inline-block keeps a sized box in an inline flow; flex and grid establish layout systems. inline-flex makes a flex container participate inline. none removes the element and its descendants from layout and accessibility exposure.

.notes-off .learning-note { display: none; }

Read the parts:

  • block / inline-block — A block participates in block layout; inline-block sits in an inline line while still accepting width and height.
  • flex / grid / inline-flex — Flex lays out children primarily along one axis; grid arranges tracks in two dimensions. inline-flex creates flex layout inside a container that participates inline.
  • none — The element contributes no layout box. This differs from merely making its color transparent, which would still leave space.

Used here: All layouts and the notes switch.

Flexbox: flex-wrap, flex-direction, flex-shrink, and order

flex-wrap: wrap lets items continue on another line. flex-direction: column stacks them. flex-shrink: 0 prevents a small item from shrinking. order changes visual order without changing source or keyboard order, so use it with care.

.hero-actions { display: flex; flex-wrap: wrap; gap: 24px; }
.status-dot { flex-shrink: 0; }

Read the parts:

  • flex-wrap: wrap — Permits a new line if the items do not fit. The default no-wrap behavior tries to keep them on one line.
  • flex-direction: column — Changes the main axis to vertical in this writing mode. Main-axis and cross-axis alignment change with it.
  • flex-shrink: 0 — Prevents an item from shrinking along the flex main axis. The status dot keeps its small round shape.
  • order — Changes only the visual arrangement. DOM order still controls reading and keyboard order, so the two should remain understandable.

Used here: Action rows, navigation, labels, and mobile footer text.

float: right

A float lets surrounding inline content flow alongside a box. Here it positions a compact filename on the right of each summary. The mobile media query hides the filename to free space.

.file-tag { float: right; }

Read the parts:

  • .file-tag — Matches the small filename span in a summary. It is a class selector, not the filename itself.
  • right — Floats that label to the right and permits summary text beside it. The phone rule later uses display: none to remove this optional label.

Used here: Workbench summary labels.

Focus: outline and outline-offset

outline paints a focus indicator without changing box dimensions. outline-offset separates it from the element. :focus-visible shows keyboard-oriented focus; :focus reveals the skip link whenever it gains focus.

:focus-visible { outline: 3px solid #5e713f; outline-offset: 5px; }

Read the parts:

  • :focus-visible — Matches focus when the browser determines a visible focus indicator is appropriate, commonly during keyboard navigation.
  • outline: 3px solid #5e713f — Draws a 3px solid green indicator around the focused element. It does not resize the element.
  • outline-offset: 5px — Moves the outline 5px away from the border. It does not move the button or link itself.

Used here: Links, buttons, summaries, and focusable code blocks.

Fonts: font-family, font-size, font-weight, and font

font-family lists fallback fonts. font-size controls text size and font-weight controls its weight. The font shorthand combines size, optional /line-height, and family; it can reset unspecified font subproperties. System fonts mean no external font service.

.eyebrow { font: 10px/1.6 var(--mono); }
em { font-family: Georgia, "Times New Roman", serif; font-weight: 400; }

Read the parts:

  • font: 10px/1.6 var(--mono) — 10px sets size; /1.6 sets a line height 1.6 times that size; the final value is the font-family list.
  • font-family — The browser tries the named fonts in order and then a generic family such as serif or monospace. A missing first font is handled by a fallback.
  • font-weight: 400 — Requests normal weight. Font weight is separate from font size; supported weights depend on the font.

Used here: Headings, labels, prose, and code.

Functions: min(), calc(), clamp(), repeat(), and minmax()

min() chooses the smallest calculation; calc() performs arithmetic; clamp(min, preferred, max) limits fluid sizing. Grid uses repeat() to repeat tracks and minmax() to set track bounds. Functions take their meaning from the property they are used in.

h1 { font-size: clamp(38px, 4.5vw, 60px); }
.section-wrap { width: min(1180px, calc(100% - 88px)); }

Read the parts:

  • clamp(38px, 4.5vw, 60px) — Prefer 4.5% of the viewport width, but never use less than 38px or more than 60px for this font size.
  • min(1180px, calc(100% - 88px)) — Calculate the parent width minus 88px, then choose that or 1180px, whichever is smaller. Keep spaces around the subtraction operator.
  • repeat() / minmax() — These are grid track functions. repeat repeats a track pattern; minmax sets a track’s lower and upper size bounds. They are not interchangeable with general size functions.

Used here: Fluid headings, centered wrappers, and grid layouts.

Grid: grid-template-columns, grid-column, and gap

display: grid creates tracks. repeat(3, 1fr) makes three equal shares; 1fr is one share of available grid space. minmax(0, 1fr) permits shrinking below content’s natural width. grid-column: 1 / -1 spans all columns. gap supplies space between items in grid or flex.

.project-grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 24px; }
.hero-foot { grid-column: 1 / -1; }

Read the parts:

  • display: grid — Turns the selected element into a grid container. Its direct children become grid items.
  • repeat(3, 1fr) — Three repeated tracks, each taking one equal share after gaps and other sizing constraints are accounted for. This is not a fixed pixel width.
  • grid-column: 1 / -1 — The slash separates starting and ending grid lines. Line 1 is the first line; -1 is the last line of the explicit grid, so the hero footer spans across it.
  • gap: 24px — Adds space between tracks. It does not add an outer margin around the grid.

Used here: Hero, About, gallery, lessons, and Contact.

List and inline decoration: list-style and box-decoration-break

list-style: none removes list markers while retaining list markup. box-decoration-break: clone paints the highlight decoration on each wrapped inline fragment rather than treating it as one sliced box.

.skill-list { list-style: none; }
.highlight-css { box-decoration-break: clone; background: var(--green); }

Read the parts:

  • list-style: none — Removes list markers. The underlying ul and li elements still express a list in HTML.
  • box-decoration-break: clone — When highlighted inline text wraps, each fragment receives its own background and padding decoration. It does not duplicate the text itself.

Used here: Technology labels and highlighted words in About.

Media queries: @media and max-width

@media applies a block only when its condition matches. max-width includes the boundary value. At 1000px this site tightens spacing; at 760px it stacks grids and wraps the header. Later matching rules override earlier rules of equal specificity.

@media (max-width: 760px) {
  .project-grid { grid-template-columns: 1fr; }
}

Read the parts:

  • @media (max-width: 760px) — The outer condition asks whether the viewport is at most 760 CSS pixels wide. It includes exactly 760px.
  • Nested braces — The outer braces contain conditional rules. The inner .project-grid braces contain that selector’s declarations. Both must be closed.
  • grid-template-columns: 1fr — Overrides only the column definition. display: grid and gap still come from earlier matching rules.

Used here: Tablet and phone overrides near the end of styles.css.

Motion: transition and prefers-reduced-motion

transition interpolates changed properties over a duration such as .2s. Here it smooths button background and transform changes. The reduced-motion query disables these effects and smooth scrolling when requested. There is no animated transition between HTML pages.

.button { transition: background .2s, transform .2s; }
@media (prefers-reduced-motion: reduce) {
  .button { transition: none; }
}

Read the parts:

  • background .2s, transform .2s — The comma separates two transitions. Each property takes 0.2 seconds to move between values when its value changes.
  • prefers-reduced-motion: reduce — This condition reads the user’s motion preference, independently of viewport width.
  • transition: none — Stops interpolation, but a hover transform would still jump immediately unless removed too. The full site also sets the hover transform to none.

Used here: Button hover styles and accessibility override.

Overflow: overflow, overflow-x, overflow-wrap, white-space, and tab-size

overflow: hidden clips artwork beyond a box. overflow-x: auto makes wide code scroll horizontally. overflow-wrap: anywhere allows long inline code or addresses to wrap. white-space: nowrap prevents chosen labels from wrapping. pre preserves whitespace; tab-size controls the visual width of tab characters.

pre { overflow-x: auto; tab-size: 2; }
code { overflow-wrap: anywhere; }
pre code { overflow-wrap: normal; }

Read the parts:

  • overflow / overflow-x — overflow governs both directions; overflow-x targets the horizontal direction. auto provides scrolling when content exceeds the box.
  • overflow-wrap / white-space — overflow-wrap allows long text to break when needed; white-space controls whitespace and wrapping behavior. pre preserves source spacing, so it uses scrolling for long lines.
  • tab-size: 2 — Sets how wide tab characters display inside the code panel. It does not rewrite tabs into two spaces in the source file.

Used here: Artwork, email link, wordmark, and code samples.

Position: relative, absolute, fixed, offsets, and z-index

relative establishes the positioning reference used by absolute descendants. absolute removes a box from normal flow; top, right, bottom, and left place it. fixed positions relative to the viewport here. z-index controls stacking of positioned elements.

.blueprint { position: relative; }
.blueprint-top { position: absolute; top: 18px; left: 20px; right: 20px; }
.skip-link { position: fixed; z-index: 10; }

Read the parts:

  • relative / absolute — The relative blueprint provides a positioning reference. Its absolute caption can then use top, left, and right offsets inside that containing block.
  • fixed — Here the skip link stays positioned relative to the viewport, even as the document scrolls.
  • z-index: 10 — Sets stacking order within the element’s stacking context. It does not mean 10px higher on the page.

Used here: Layered illustrations and skip link.

Pseudo-classes and pseudo-elements

:hover matches pointer hover; :focus and :focus-visible match focus states. :first-child, :last-child, and :nth-child(2) match positions among siblings. :not(.eyebrow) excludes a class. ::marker styles a disclosure marker; ::before and ::after represent generated boxes and receive the global box-sizing reset.

.code-lesson summary::marker { color: #687d50; }
.mini-layout div:nth-child(2) { padding-block: 18px; }

Read the parts:

  • :hover / :focus — These match a state of an existing element. They do not require a class to be added by JavaScript.
  • :nth-child(2) — Matches an element that is the second element child among its siblings. The example gives the middle miniature browser panel extra height through padding.
  • ::marker — A pseudo-element representing the list or disclosure marker. Two colons distinguish pseudo-elements from pseudo-classes in this syntax.
  • :not(.eyebrow) — Matches elements that do not have the eyebrow class, when combined with the rest of the selector.

Used here: Hover, keyboard focus, summary markers, and illustration details.

Scrolling: scroll-behavior, scroll-padding-top, and scroll-margin-top

scroll-behavior: smooth animates in-page scrolling. scroll-padding-top reserves space at the scroll container’s top. scroll-margin-top adds space around a destination when scrolled into view. These affect fragment navigation, not loading another page.

html { scroll-behavior: smooth; scroll-padding-top: 30px; }
.code-lesson { scroll-margin-top: 24px; }

Read the parts:

  • scroll-behavior: smooth — Asks the browser to animate programmatic or fragment scrolling in that scroll container. It is not a page-loading animation.
  • scroll-padding-top: 30px — Reserves top space inside the scroll container when it brings destinations into view.
  • scroll-margin-top: 24px — Belongs to the destination element and gives it extra top clearance when scrolled into view.

Used here: In-page destinations and lesson links.

Selectors: type, class, id, attribute, and combinators

body selects a tag, .hero a class, #main an id, and [hidden] an attribute. [aria-pressed="true"] matches a value. A space selects descendants, > direct children, and + the next sibling. Commas group selectors. These are also the selector syntax used by JavaScript queries.

.notes-off .learning-note { display: none; }
p + p { margin-top: 15px; }
.filter-button[aria-pressed="true"] { background: var(--ink); }

Read the parts:

  • .class / #id / [attribute] — A dot matches a class, # matches an id, and square brackets test an HTML attribute. These symbols are outside the declaration braces.
  • Space / > / + — A space selects descendants at any depth; > restricts to direct children; + selects the immediately following element sibling.
  • [aria-pressed="true"] — The quoted value must match the attribute’s text. JavaScript updates that attribute, which causes the styling to match a different button.

Used here: Shared CSS rules and state-driven styling.

Sizing: width, height, min-width, min-height, and max-width

width and height size boxes; minimum and maximum properties constrain them. min-width: 0 lets a grid item shrink so long code does not stretch the page. max-width limits reading or illustration width; min-height reserves room for the blueprint.

.project-card { min-width: 0; }
.guide-main { max-width: 1000px; }

Read the parts:

  • width / height — Set the box’s dimensions in the horizontal and vertical directions. With border-box, padding and borders fit inside these dimensions.
  • min-width: 0 — Lets a grid or flex child shrink below its content’s default minimum size. This is useful for a long code sample inside a narrow column.
  • max-height: 480px — Caps the complete-code panel’s height. Combined with overflow: auto, long samples scroll vertically inside the panel instead of filling many screens.
  • min-height / max-width — A minimum height reserves space even with little content. A maximum width prevents a reading area from becoming too wide.

Used here: Cards, illustrations, and reading pages.

Spacing: margin, padding, and logical edges

margin is space outside the border; padding is space inside. Two shorthand values mean block-direction then inline-direction in this horizontal writing mode. margin-inline: auto centers a width-constrained block. padding-block and margin-inline follow writing direction; top/right/bottom/left are physical edges.

.section-wrap { margin-inline: auto; }
.card-content { padding: 23px; }
.guide-step { padding-block: 38px; }

Read the parts:

  • margin / padding — Margin separates the outside of a box from other boxes. Padding separates content from its own border.
  • padding: 20px 30px — Two values mean top/bottom then left/right. Four values would follow top, right, bottom, left.
  • padding-block / margin-inline — In this horizontal English layout, block refers to top/bottom and inline to left/right. These logical properties adapt to writing direction.
  • margin-inline: auto — Shares free horizontal space on both sides of a width-constrained block, centering it.

Used here: Wrappers, section rhythm, cards, and lesson panels.

Tables: border-collapse and vertical-align

Table-specific layout lets the device reference compare formats without turning each cell into a separate card. Width, text alignment, padding, and borders combine with these two properties.

.table-scroll table { width: 100%; border-collapse: collapse; }
.table-scroll th, .table-scroll td {
  text-align: left;
  vertical-align: top;
  padding: 12px;
  border-bottom: 1px solid var(--line);
}

Read the parts:

  • border-collapse: collapse — Adjacent table cells share borders. This avoids the separated-cell border model and gives the rows continuous dividing lines.
  • vertical-align: top — Aligns cell contents at the top of their row, so a short viewport label lines up with a longer explanation. This is table-cell alignment; it does not replace align-items in flex or grid.
  • width: 100% / text-align: left — The table fills its parent’s available width. Cell text aligns left independently of that overall table width.
  • .table-scroll th, .table-scroll td — Two descendant selectors separated by a comma give the same spacing and borders to header cells and data cells.

Used here: The step-7 viewport comparison table.

Text: line-height, letter-spacing, text-align, and text-decoration

line-height controls line spacing; unitless values scale with font size. letter-spacing adjusts character spacing; text-align centers inline content. text-decoration adds or removes underlines; text-underline-offset moves an underline away from text.

nav a:hover { text-decoration: underline; text-underline-offset: 5px; }

Read the parts:

  • line-height / letter-spacing — Line height separates lines of text; letter spacing adjusts space between characters. They solve different spacing problems.
  • text-align: center — Centers inline text inside its box. It does not center the box itself.
  • text-decoration / text-underline-offset — The first adds an underline or other decoration; the second adjusts how far below the text an underline sits.

Used here: Readable body copy, tight headings, centered artwork, and link affordances.

Transforms: rotate(), skewX(), and translateY()

transform changes the visual position or shape without rearranging normal layout. rotate() tilts an element; skewX() shears it horizontally; translateY() moves it vertically. Degrees measure angles and a negative Y translation moves upward.

.layer { transform: rotate(-7deg) skewX(-7deg); }
.button:hover { transform: translateY(-2px); }

Read the parts:

  • rotate(-7deg) — Tilts the visual box seven degrees counterclockwise. The underlying layout slot is unchanged.
  • skewX(-7deg) — Shears the box along the horizontal axis; it is different from rotating the entire box.
  • translateY(-2px) — Moves the visual box upward two pixels. Multiple transform functions are composed in their written order, and changing that order can change the result.

Used here: Blueprint layers, swatches, and button hover.

Units and special values: px, %, em, vw, fr, auto, and none

px is a CSS pixel; % depends on a property’s reference size; em relates to font size; vw is one hundredth of viewport width; fr distributes grid space. auto lets a property use its automatic sizing or spacing behavior; none disables the applicable feature. Zero usually needs no length unit.

h1 { font-size: clamp(38px, 4.5vw, 60px); }
.project-grid { grid-template-columns: repeat(3, 1fr); }

Read the parts:

  • px / % / vw — px is a CSS pixel; % uses the reference defined by the property; vw uses viewport width. A physical display pixel is not always one CSS pixel.
  • em / fr — em is relative to font size (for font-size itself, the inherited size); fr divides available grid track space. fr is not a general-purpose width unit outside grid track sizing.
  • auto / none / 0 — auto delegates the applicable calculation to layout; none disables an applicable feature; 0 is a numeric zero and commonly needs no length unit. Their meanings depend on the property.

Used here: Layout, typography, spacing, and state rules.
